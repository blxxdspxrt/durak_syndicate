# Syndicate — «Дурак» в Telegram WebApp

Мини-приложение Telegram: карточная игра «Дурак» с двумя режимами и вторым
командным режимом **Синдикат** (2×2 и 2×2×2).

Стек: Next.js 16 (App Router), React 19, Tailwind v4, Supabase (Postgres + Realtime).

---

## 🚀 Быстрый старт

### 1. Переменные окружения

Скопируйте `.env.example` в `.env.local` и заполните:

```bash
cp .env.example .env.local
```

| Переменная | Назначение |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | URL проекта Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Публичный ключ (клиент) |
| `SUPABASE_SERVICE_ROLE_KEY` | **Секретный** ключ сервера (обход RLS). Нужен для защиты карт |
| `TELEGRAM_BOT_TOKEN` | Токен бота для проверки подписи `initData` |
| `CRON_SECRET` | *Необязательно.* Секрет для фонового `/api/cron/sweep` (мониторинг 24/7) |

> ⚠️ `SUPABASE_SERVICE_ROLE_KEY` — только сервер. Никогда не добавляйте его в
> `NEXT_PUBLIC_*` и не коммитьте `.env.local`.

### 2. Миграции БД

Выполните по порядку в Supabase → SQL Editor:

1. `supabase/migrations/001_game_states.sql` — базовые игровые поля
2. `supabase/migrations/002_security.sql` — **RLS-защита** (закрывает карты и балансы)
3. `supabase/migrations/003_game_state_modes.sql` — режимы и команды
4. `supabase/migrations/004_presence.sql` — присутствие игроков (мониторинг 24/7)
5. `supabase/migrations/005_economy.sql` — экономика (места, ELO, Влияние)
6. `supabase/migrations/006_penalties_notifications.sql` — таймер, AFK-вылеты, штрафы, уведомления
7. `supabase/migrations/007_per_mode_penalties.sql` — раздельные нарушения/баны по режимам

> Применяйте `002_security.sql` **после** добавления `SUPABASE_SERVICE_ROLE_KEY`,
> иначе сервер потеряет доступ к `game_states`.

### 3. Запуск

```bash
npm install
npm run dev

# автотесты игрового движка (без БД)
npm run test:engine
```

## 🔐 Модель безопасности

Игра построена по принципу **server-authoritative**: вся раздача, проверка
правил и расчёт ставок происходят на сервере.

- **Клиент (anon-ключ)** больше не читает `game_states`, `users`, `game_history`.
  Эти таблицы закрыты политиками RLS (`revoke all ... from anon`).
- **Сервер (service_role)** — единственный, кто видит колоду и чужие руки.
- Игровое состояние отдаёт `GET /api/games/state/[id]`, причём:
  - свои карты — полностью;
  - чужие руки — только количество (`{ count }`);
  - колода — только `deck_count` (порядок карт не покидает сервер).
- Все мутирующие ручки (`tables`, `join`, `leave`, `games/*`) требуют
  подписанный Telegram `initData` (`authenticateRequest`). Флаг `isCreator`
  и `userId` из тела запроса больше не считаются доверенными.
- Расчёт ставки идемпотентен (защита от двойного начисления) и zero-sum:
  сколько проигравшие заплатили — столько победители и получили.

## 🃏 Режимы игры

| Режим | Описание |
|---|---|
| **Классический** (подкидной) | Подкидывать карты того же ранга может любой, кроме защитника |
| **Переводной** | Дополнительно: защитник может **перевести** ход, подложив карту того же ранга |
| **Синдикат** | Командная игра 2×2 или 2×2×2. Порядок хода перемешан так, чтобы напарники не сидели рядом (2×2 → `[1,3,2,4]`, 2×2×2 → `[1,3,5,2,4,6]`). Команда выигрывает, когда все её игроки вышли |

Ход (`/api/games/move`) принимает действия: `attack`, `defend`, `transfer`,
`take`, `bito`. Вся валидация — в `lib/game-engine.js` (чистые функции).

### Правила захода (автоматика)

- **«Беру» недоступно, если все карты на столе отбиты.** Защитник не может
  забрать свои же отбитые карты — сервер отклонит такой ход.
- **Авто-«Бито».** Как только последняя карта отбита и подкидывать больше
  некому/некуда (у атакующих нет карт нужного ранга, набрано 6 карт на столе,
  либо неотбитых не меньше, чем карт в руке защитника) — заход закрывается сам:
  стол уходит в отбой, из колоды дораздаются карты, защитник становится атакующим.
- **Таймер хода — динамический.** Время выбирается при создании стола
  (15 / 30 / 45 / 60 с) и берётся из `tables.turn_time` → `state.turn_seconds`.
- **1-я просрочка** — партия НЕ завершается, игроку автоматически применяется
  действие: не отбился → «Взял»; всё отбито → «Бито»; стол пуст → «Пас».
- **2-я просрочка ПОДРЯД** — игрок «вылетает» (AFK): карты уходят в отбой,
  бай-ин сгорает, начисляются санкции (см. ниже), остальные доигрывают.
  В 1v1 и 2×2 партия завершается сразу — выживший / вторая команда берёт 100%.
- **Выход из-за стола во время партии** приравнен к AFK-вылету (та же лестница
  санкций). Выход уже победившего наблюдателя партию не завершает.
- **Таймаут не зависит от клиента.** Любой запрос к столу (`/state`, `/move`,
  `/timeout`) сначала прогоняет серверную проверку `reconcileTimeout`: если
  дедлайн прошёл, сервер САМ применит просрочку. Клиент лишь ускоряет (3
  попытки с интервалом 1 с), поэтому потерянный пакет игру не вешает.
- **Наблюдатели.** Победитель (у кого закончились карты) остаётся за столом
  наблюдателем и не ходит, пока партия не закончится (не объявлен «дурак»).

## 💰 Экономика (рейк, призовые, ELO, Влияние)

Всё считается в `lib/economy.js` (чистые функции) и применяется в
`lib/game-settle.js`. Суммы — целые доллары, округление **вниз**.

**Единый рейк системы — 8%** от суммы бай-инов:
`чистый призовой фонд = ставка × игроков × 0.92`.

### Классика (FFA: 2–6 игроков)

Деньги — доля чистого фонда по занятому месту («дурак» получает `$0`):

| Игроков | 1-е | 2-е | 3-е | 4-е | 5-е | 6-е |
|---|---|---|---|---|---|---|
| 2 | 100% | 0 | | | | |
| 3 | 70% | 30% | 0 | | | |
| 4 | 50% | 30% | 20% | 0 | | |
| 5 | 45% | 25% | 18% | 12% | 0 | |
| 6 | 40% | 24% | 18% | 11% | 7% | 0 |

ELO по местам (не зависит от ставки): 2 → `+20 / -20`; 3 → `+25 / +8 / -33`;
4 → `+28 / +12 / -2 / -38`; 5 → `+30 / +15 / +3 / -10 / -38`;
6 → `+35 / +18 / +6 / -4 / -15 / -40`.

### Синдикат (прогресс = Влияние, ELO не меняется)

- **2×2** (4 игрока, 2 синдиката): победивший синдикат забирает весь чистый
  фонд пополам — по 50% каждому (≈ +84% к личному бай-ину), проигравший — `$0`.
  Влияние: победители `+22`, проигравшие `-18`.
- **2×2×2** (6 игроков, 3 синдиката): 1-е место — `70%` фонда (по `35%` каждому),
  2-е место — `30%` (по `15%` каждому), 3-е («дураки») — `$0`.
  Влияние: `+32` / `+6` / `-28`.

### Досрочное завершение (выход игрока / таймаут)

Проигравший получает `$0` и теряет бай-ин, а **чистый фонд делится поровну**
между всеми остальными участниками партии (округление вниз). ELO и Влияние
при этом не меняются.

> Бай-ин должен быть обеспечен балансом: сесть за стол / создать стол можно
> только при `dollars >= ставка`.

## ⚖️ Штрафы за выход / AFK

Лестница санкций живёт в `lib/economy.js` (чистые правила, покрыты тестами),
применяется в `lib/penalties.js`. Счётчик обнуляется после 24 часов без нарушений.

| Нарушение | Штраф | Бан поиска/создания/посадки |
|---|---|---|
| Первое в жизни аккаунта | только предупреждение | — |
| 1-е в окне 24 ч | ½ штрафа «последнего места» (напр. −19 ELO при 4 игроках) | — |
| 2-е | полный штраф (напр. −38 ELO) | — |
| 3-е | ×1.15 к штрафу | 15 мин |
| 4-е | ×1.30 | 30 мин |
| 5-е и далее | +0.15 за каждый шаг | ×2 каждый раз (60, 120 мин…) |

- **Бай-ин сгорает всегда** — он остаётся в банке стола и достаётся выжившим.
- **Классика и Синдикат считаются РАЗДЕЛЬНО.** У каждого режима свой счётчик
  нарушений, своя «первая санкция» и свой бан: провинился в Синдикате —
  в Классику играть можно, и наоборот. Хранится в `users.penalties` (jsonb).
- **Очки разные**: в Классике меняется ELO, в Синдикате — Влияние.
- **Невиновный напарник**: в 2×2 не штрафуется по Влиянию и получает назад
  **75% ставки**; в 2×2×2 получает мягкий **−8** Влияния (возврата нет).
- **Противники**: 2×2 — забирают призовой фонд (+22 Влияния каждому);
  2×2×2 — доигрывают за 1-е и 2-е места по стандартной таблице (+32 / +6).
- О каждой санкции игрок узнаёт двумя способами: сообщение в личку Telegram
  и уведомление в мини-аппе. **В тексте всегда указан режим**, в котором
  вынесена санкция (и что именно заблокировано).

> ⚠️ **Первое нарушение в жизни аккаунта** (в каждом режиме — своё «первое»)
> наказывается **только предупреждением**: ELO/Влияние и бан не применяются,
> но бай-ин всё равно сгорает. Если нужно штрафовать и за него — в
> `lib/economy.js` → `leaveSanction` уберите ранний `if (!warned) return …`.

## 🔔 Уведомления

- Колокольчик в шапке показывает **красный кружок**, пока есть непрочитанные.
- По клику кружок сбрасывается сразу (все помечаются прочитанными), и
  открывается панель-«облачко» с коротким хвостиком к кнопке.
- Внутри два списка — **«Непрочитанные»** (сверху) и **«Прочитанные»**,
  у каждого уведомления кнопка **«Удалить»**.
- Панель растягивается по содержимому, но не выше **⅓ экрана** — дальше
  прокрутка внутри.
- Закрывается кликом по свободному месту или повторным кликом по колокольчику.
- Уведомления лежат в БД (`notifications`) и исчезают только по воле игрока.

## 🛰 Мониторинг присутствия (24/7)

Счётчик **«Играет»** — это уникальные игроки, реально сидящие за столами, а не
сумма счётчиков (как было раньше). Данные всегда пересчитываются из таблицы
`table_players`, поэтому «призраков» и дубликатов в списке больше нет.

1. Пока клиент открыт, он раз в секунду шлёт `POST /api/tables/heartbeat`,
   обновляя `table_players.last_seen_at`, и сразу получает свежие столы и статистику.
2. Любой запрос лобби (`GET /api/tables`, `heartbeat`, `quick-search`) запускает
   **чистку**: игроки без «пульса» дольше `PRESENCE_STALE_MS` (20 c) удаляются,
   счётчики столов пересчитываются, а столы без игроков **самоликвидируются**
   (вместе с их `game_states`). Если ушёл **владелец**, а игроки остались —
   права **переходят случайному** оставшемуся игроку (стол продолжает жить).
3. **Один игрок — один стол**: при создании стола или посадке за новый игрок
   автоматически выходит из всех прежних — дубликатов «один игрок в куче столов» нет.
4. Если стол закрылся (все вышли) — `heartbeat` вернёт `removed: true`, и клиент
   сам уйдёт в лобби, как и все остальные участники.
5. Для полного 24/7 без открытых клиентов есть фоновый «дворник»
   `GET /api/cron/sweep`. Направьте на него любой планировщик (cron-job.org,
   GitHub Actions, Vercel Cron) — он просто вызовет чистку вне зависимости от
   того, есть ли кто-то в приложении.

#### Что такое `CRON_SECRET`

`CRON_SECRET` — это ваш собственный «пароль» для служебной ручки
`/api/cron/sweep`. Сама по себе она не хранит секретов, но её вызов запускает
запись в БД (удаление «призраков» и пустых столов), поэтому её нельзя
оставлять открытой для кого угодно.

Как это работает:

- если `CRON_SECRET` **не задан** — ручка открыта (удобно локально: можно
  дёрнуть её вручную браузером);
- если `CRON_SECRET` **задан** — ручка отвечает `401`, пока в запросе нет
  заголовка `Authorization: Bearer <CRON_SECRET>`.

То есть вы придумываете любую длинную случайную строку, кладёте её и в
переменные окружения приложения (Vercel + `.env.local`), и в настройки
планировщика — и только ваш планировщик сможет запускать чистку.

```bash
# пример вызова вручную
curl -H "Authorization: Bearer $CRON_SECRET" https://<ваш-домен>/api/cron/sweep
```

> Важно: реальное «каждую секунду» обеспечивают `heartbeat`-и из открытых
> клиентов. Cron — это лишь подстраховка для случаев, когда приложение
> закрыто у всех (на Hobby-плане Vercel cron запускается максимум раз в
> сутки, на Pro — раз в минуту).

> Лимиты настраиваются константами `PRESENCE_STALE_MS` и `NEW_TABLE_GRACE_MS`
> в `lib/presence.js`.
